# 动画工具与 Skills 能力地图

更新时间：2026-07-26

## 当前工具分工

| 工具 / Skill | 最适合的职责 | 现在是否使用 | 备注 |
| --- | --- | --- | --- |
| Remotion | 正片装配、真人、录屏、字幕、参数化模板、批量渲染 | 主用 | 当前十个样片已在一个工程内参数化管理 |
| HyperFrames | HTML 动画、GSAP、短样片、特殊转场、快速视觉探索 | 保留 | 新且有潜力，适合实验，不急于成为唯一主引擎 |
| `remotion-markup` | 帧驱动动画、媒体嵌入、Sequence、可编辑结构 | 现在用 | 禁用 CSS 动画，全部由帧时间驱动 |
| `remotion-captions` | JSON 字幕、词级时间、语义高亮 | 正式片再用 | 字幕 rail 常驻，高潮词少量脱离 rail |
| `remotion-interactivity` | 让 Studio 中的元素更容易调整 | 模板定型后用 | 适合长期母版，不影响今晚风格判断 |
| `talking-head-recut` | 真人口播上的信息卡、画中画、证据窗口 | 借机制 | 默认“原片不动 + 偶发卡片”不满足全程动态，需要自定义外壳 |
| `embedded-captions` | 可靠字幕轨与高潮嵌字 | 借原则 | 不采用每个词都弹跳的默认社媒效果 |
| `motion-graphics` | 10 秒内的字效、数字、图表和短转场 | 局部使用 | 适合做组件，不适合独占整条口播片 |
| `general-video` | 自定义长视频、复杂多段组合 | 正式片可用 | 当专用工作流不匹配时再使用 |
| Hallmark | 网页/UI 的反 AI 套路设计方法 | 只参考 | 未安装；不是视频 Skill，不照搬它的网页门禁和主题轮盘 |
| huashu-design | 高保真原型、设计方向探索 | 低权重参考 | 保留“拒绝默认 AI 味”和“持续元素变形”两点即可 |

## 为什么长期主工具选 Remotion

- 真人视频、录屏、字幕和图形可以作为明确的组件与时间段管理。
- 同一套模板可以通过 props、JSON 和字幕数据反复生成。
- Studio、字幕、媒体和渲染文档更成熟。
- 当前工程已经验证 1080×1920、30fps 和批量渲染。
- 十个样片均为 180 帧，实际输出规格一致，便于横向比较。

## HyperFrames 仍然值得保留的原因

- 普通 HTML/CSS 与 GSAP 的自由度高，Agent 容易直接修改。
- 对连续形变、路径动画、网页元素和短动效非常方便。
- 官方工作流覆盖真人包装、字幕、短动效、媒体处理和设计规范。
- 可以作为“视觉实验室”，探索成功后再移植进 Remotion 长期母版。

HyperFrames 核心维护者在 [HyperFrames vs Remotion #318](https://github.com/heygen-com/hyperframes/issues/318) 中说明：它受到 Remotion 启发，主要为任意 HTML/CSS、GSAP 等独立时间轴和 Agent 创作工作流解决问题；同时它不试图替代 Premiere 或 Resolve。

## 暂时不安装的工具

### Motion Canvas

适合旁白同步的矢量图解和数学/代码讲解，但会增加一套 TypeScript 场景体系。第一条视频的主要难点是真人、录屏和账号调性，不是矢量讲解能力。

### Rive

适合状态机、交互组件和数据绑定动画。以后可以把一个高频组件做成 Rive，但它不是当前线性视频生产链的主工具。

### Revideo

适合 generator 式的程序化视频和批量输出，与现有 Remotion / HyperFrames 能力重复。

## 现在真正缺少的东西

- 用户本人的竖屏口播测试素材。
- 第一条视频使用的真实爆款对标素材。
- 工具的真实录屏，而不是样片里的结构占位。
- 一段 15～20 秒的锁定口播，用于测试字幕、脸部大小和动画节奏。
- 从十个方向中选出的视觉底盘与运动规则。

因此，当前不应继续扩充工具数量。
